# WPF実出力性能検証

最終更新日: 2026-08-01  
状態: 基準測定完了、Phase 2目標値は開発者承認済み

## 1. 結論

WPF + LibVLCSharp + LibVLCの実`VideoView`経路で、初回保証範囲の上限を代表する3条件を
各5回測定し、15回すべてに合格した。すべてD3D11VAとWASAPIを使用した。

| 代表条件（すべて60秒） | 操作可能まで 中央値 / 最大 | 映像準備 中央値 / 最大 | 50%シーク 中央値 / 最大 | 90%シーク 中央値 / 最大 |
| --- | ---: | ---: | ---: | ---: |
| MP4 1080p60 | 1085 / 1173 ms | 684 / 708 ms | 447 / 463 ms | 751 / 767 ms |
| MP4 4K60 | 1044 / 1196 ms | 705 / 719 ms | 452 / 457 ms | 1040 / 1068 ms |
| WMV 1080p60 | 1011 / 1039 ms | 593 / 601 ms | 1100 / 1114 ms | 875 / 902 ms |

映像準備の最大は719 ms、シークの最大は1114 msだった。WMVは50%シーク、4K MP4は
90%シークがそれぞれ最も遅く、コーデックやシーク先によって最大箇所が異なる。

## 3. 測定定義

`scripts/measure-phase2-wpf-performance.ps1`がReleaseビルドのWPFスパイクを新規プロセスで起動する。
Windowsのファイルキャッシュは強制消去しない。したがって本書の「コールド」は毎回プロセスを
新規起動する**プロセスコールド**であり、ディスクキャッシュコールドではない。各条件の1回目も
結果に残し、5回の中央値と最大値を採用した。

- 操作可能: プロセス開始からWPF DispatcherのApplicationIdleまで。
- 映像準備: オープン要求から、LibVLCのVout生成と再生時計100 ms到達の遅い方まで。
- 音声準備: オープン要求からWASAPI出力モジュール開始ログまで。
- シーク: `Position`設定から、再生時計がシーク先 + 100 msへ到達するまで。
- 速度・音量: 設定要求から読み戻し値が要求値へ変わるまで。
- アイドル資源: Dispatcher準備後、動画を開く前の2秒間。
- 再生資源: 映像準備後、シーク前の3秒間。

映像準備とシークはイベントによる代理測定であり、光学センサーを使った画素変化測定ではない。
ただし同じWPF Voutが`PrintWindow`で実描画されることは先行検証済みである。音声もWASAPI開始の
代理値であり、スピーカー出力をマイクで測定した値ではない。

## 4. 資源使用量

CPUは全24論理プロセッサに対する当該プロセスの比率、GPUは`nvidia-smi`のシステム全体値である。

| 条件 | アイドルCPU 中央値 | 再生CPU 中央値 / 各回最大の最大 | 再生Working Set 中央値 / 最大 |
| --- | ---: | ---: | ---: |
| MP4 1080p60 | 0.24% | 1.06% / 2.82% | 283 / 289 MiB |
| MP4 4K60 | 1.07% | 0.91% / 2.98% | 492 / 495 MiB |
| WMV 1080p60 | 0.25% | 1.05% / 3.96% | 266 / 269 MiB |

`nvidia-smi`のGPU全体使用率と動画デコード使用率は、整数パーセントのサンプルでは全件0%だった。
これは「GPU未使用」を意味しない。全15回のLibVLCログでD3D11VAが選択されており、この低ビット
レートの合成素材ではNVIDIAの整数カウンターの1%未満だったと解釈する。GPU使用率の細かな比較には
PresentMon、GPUView等による追加測定が必要である。

速度1.5倍への反映は最大1.4 ms未満、音量50%への反映は最大0.3 ms未満だった。これらは
バックエンド値の反映時間であり、WPFコントロールの描画遅延は含まない。

## 5. 確定したPhase 2目標値

最大実測値をそのまま閾値にせず、同じ基準PC・ハードウェアデコード有効・プロセスコールド条件で
約25～40%の余裕を持たせ、次の目標値を2026-08-01に開発者承認により確定した。

| 項目 | 確定目標 | 実測最大 | 余裕 |
| --- | ---: | ---: | ---: |
| 操作可能なメインウィンドウ | 1500 ms以内 | 1196 ms | 304 ms |
| 映像・音声の準備 | 1000 ms以内 | 719 ms | 281 ms |
| 50% / 90%シーク | 1500 ms以内 | 1114 ms | 386 ms |
| 速度・音量のバックエンド反映 | 100 ms以内 | 1.4 ms未満 | 98 ms以上 |

本実装ではUI、設定読込、単一起動処理等が追加されるため、Phase 4以降も同じスクリプト相当の測定を
継続し、閾値超過時は内訳を測る。
