# 爆裂おさかな工房 開発計画

最終更新日: 2026-08-09
現在のフェーズ: Phase 4進行中（初回リリース品質確認）
計画の基準: `docs/develop-process.md`

## 1. この文書の役割

この文書は、プロジェクト全体の進行状況、次に行う作業、フェーズ移行条件、重要な判断を引き継ぐための生きた計画書である。

- セッション開始時に必ず読み、現在地と次の作業を確認する。
- 作業開始前に、該当タスクの状態を `未着手` から `進行中` に変更する。
- 作業終了時に、完了した項目、次の作業、阻害事項、決定事項を更新する。
- 要求や方針が変わった場合は、実装より先にこの計画と関連仕様を更新する。
- 詳細な機能実装状況は、Phase 1 で作成する `docs/specifications/todo.md` で管理する。

## 2. 開発方針

1. 仕様、技術、UIの順に合意を形成してから、本実装を進める。
2. 不明点を推測で確定せず、選択肢、影響、推奨案を整理して開発者に確認する。
3. UI段階ではモックを活用し、再生基盤などの本実装と切り離して早期に操作性を検証する。
4. 実装は小さな縦の機能単位に分割し、各単位でテスト、自己レビュー、コミットを行う。
5. Windows 11での品質を優先し、他OS対応を妨げない設計は目指すが、初回リリースを遅らせる必須条件にはしない。
6. 起動、ファイルオープン、再生開始までの応答性を、機能の正しさと並ぶ重要な品質として扱う。

### 最初に解決する論点

優先度「高」の項目から確認する。技術選定で検証すべき項目は、Phase 1で結論を固定せず、制約と期待結果を明記してPhase 2へ送る。

| 優先度 | 論点 | 確認する内容 |
| --- | --- | --- |
| 高 | 多重起動とファイル引き渡し | 2回目の起動を拒否するだけか、既存ウィンドウへ指定動画を渡して前面表示するか |
| 高 | 動画識別子 | プロファイルを絶対パスで識別するか、移動・改名や同名ファイルをどう扱うか |
| 高 | 再生開始位置 | 手動登録位置のみ保存するか、最後の再生位置も保存するか、優先順位をどうするか |
| 高 | 連続再生 | 動画終了後の停止、次項目への遷移、欠損ファイル、末尾到達時の動作 |
| 高 | 音量ブースト | 100～500%の品質、安全性、クリッピング対策と、環境による制約をどう扱うか |
| 高 | 対応形式 | 拡張子だけでなく、mp4/wmv内のコーデック差異をどこまで保証するか |
| 中 | プレイリスト永続化 | 保存形式、保存場所、複数プレイリスト、名前変更、重複登録の扱い |
| 中 | 最近開いたファイル | 欠損項目の表示・削除、同一ファイルの再オープン時の並び順 |
| 中 | 長押し2倍速 | 元の速度への復帰、ドラッグとの判定、長押し開始までの時間 |
| 中 | シークサムネイル | 生成タイミング、キャッシュ、長尺動画での性能、未生成時の表示 |
| 中 | フルスクリーン | コントロール表示、自動非表示、Esc操作、複数ディスプレイ時の対象 |
| 中 | 設定・データ保存先 | ポータブル性と、書き込み不可の配置先（例: Program Files）の扱い |
| 中 | ファイル関連付け | インストーラーなしで、関連付けの設定・解除をどのように提供するか |
| 低 | 他OS対応 | 初回リリースで検証するOSと、Windows固有機能の抽象化範囲 |

### 完了条件

- `specs.md` に、正常系、主要な異常系、永続化ルール、初期値、対象外が記載されている。
- `todo.md` の各項目が、完了・未完了を客観的に判定できる。
- 高優先度の未決事項が解消されているか、Phase 2の検証課題として明示されている。
- 開発者による仕様レビューが完了している。

## 5. Phase 2: 開発スタックの決定

### 目的

必須の動画再生機能、Windowsデスクトップ連携、配布形態、応答性能を満たす技術構成を、比較と小規模検証に基づいて決定する。

### 評価軸

- mp4/wmvおよび実際に必要なコーデックの再生互換性
- シーク、速度変更、音量ブースト、フレーム取得の実現性
- コントロールオーバーレイ、ホバーポップアップ、右クリックメニュー、複合マウスジェスチャーの表現力
- 別プレイリストウィンドウ、将来の複数メインウィンドウ、フルスクリーン、複数ディスプレイへの拡張性
- UIロジックと再生処理を分離し、モックを使ってPhase 3のUIレビューを行えるか
- 起動時間、ファイルオープンから再生開始までの時間、メモリ使用量
- 単一プロセス化、コマンドライン、ドラッグ&ドロップ、ファイル関連付け
- 複数ウィンドウ、フルスクリーン、複数ディスプレイ対応
- 単体配布または依存ファイル同梱の容易さ
- テスト容易性、保守性、ライブラリのライセンスと継続性
- Windows優先と将来の他OS対応のバランス

## 7. Phase 4: 動作の作り込み

### 目的

承認済みの仕様とUIに従い、小さく検証可能な単位で機能を完成させる。

### 推奨実装順

依存関係と早期のリスク検出を優先し、次の縦スライスで進める。各スライスには、実装、テスト、仕様・todo更新、自己レビューを含める。

1. アプリ基盤
   - プロジェクト構成、ログ、エラー処理、設定保存、テスト基盤
2. 最小再生経路
   - 起動、ファイル選択、mp4/wmv読み込み、自動再生、基本エラー表示
3. 再生コントロール
   - 再生・一時停止、シーク、時刻、速度、ショートカット
4. 音声
   - 音量、ホイール操作、ミュート、ブースト、プロファイル復元
5. Windows連携
   - ドラッグ&ドロップ、起動引数、単一起動、最近開いたファイル、関連ディレクトリ
6. 表示モード
   - フルスクリーン、右クリックメニュー、複数ディスプレイ、長押し2倍速
7. 動画プロファイル
   - 動画識別、音量、再生開始位置、マーク、データ破損時の復旧
8. プレイリスト
   - 別ウィンドウ、永続化、追加、削除、並べ替え、欠損表示、連続再生
9. サムネイル
   - 生成、表示、キャッシュ、長尺動画での性能とキャンセル
10. 配布とリリース品質
    - ファイル関連付け手順、パッケージ、性能測定、互換性確認、利用文書

### 横断的な品質確認

- ユニットテスト: 設定、プロファイル、プレイリスト、時刻・音量・速度変換などのロジック
- 統合テスト: 再生バックエンド、永続化、単一起動、コマンドライン引数
- UIテスト: 主要操作、ウィンドウ遷移、ショートカット、エラー状態
- 手動テスト: 実動画、コーデック差、複数ディスプレイ、DPI、音声出力環境
- 性能テスト: コールドスタート、ファイルオープン、再生開始、シーク、サムネイル生成
- 耐障害性: 欠損・破損・非対応・アクセス拒否ファイル、壊れた設定、書き込み不可
- 配布確認: クリーンなWindows 11環境での起動と必須シナリオ

### 完了条件

- `docs/specifications/todo.md` の初回リリース必須項目がすべて完了している。
- 自動テスト、主要な手動テスト、性能基準を満たしている。
- 重大な既知不具合がなく、残課題が文書化されている。
- 配布物をクリーン環境で検証し、再現可能なビルド手順がある。
- 開発者がリリース候補を承認している。

## 9. セッション運用

### セッション開始時

1. `docs/develop-process.md` を読む。
2. この `docs/project-plan.md` を読み、現在のフェーズ、進行中項目、次の作業、阻害事項を確認する。
3. 存在する場合は `docs/specifications/specs.md` と `docs/specifications/todo.md` の関連箇所を読む。
4. リポジトリの状態と直近の変更を確認し、文書の現在地と一致するか確認する。
5. 今回扱う項目を `進行中` にし、作業範囲と完了条件を明確にしてから着手する。

### セッション終了時

1. 完了した作業と検証結果を関連文書へ反映する。
2. この文書のフェーズ状態、チェック項目、次の作業、阻害事項、決定ログを更新する。
3. `specs.md` と `todo.md` が存在する場合は、実装との整合を確認する。
4. 自己レビューを行い、未確認事項や残存リスクを記録する。
5. 次のセッションが追加調査なしで再開できる状態にする。

## 11. 阻害事項

技術的な阻害事項はない。初回リリース候補の機能実装は完了した。CI/CDは整備対象外とし、次はローカル品質ゲート、配布物、利用文書を整備する。WPF実出力検証は音声をミュート固定して行い、実音声・聴感品質はPhase 2の合格証跡を維持した。製品ウィンドウの起動スモークではログ上の表示開始と応答を確認したが、検証プロセスからウィンドウハンドルを取得できず強制終了したため、次の品質ゲートで実画面の正常終了を再確認する。Windows高コントラスト専用配色も同品質ゲートで必要性を再評価する。

基本再生、保証範囲、性能目標、速度変更後の定常品質、500%音量の実WASAPI出力と聴感、サムネイル生成と主再生競合、エッジケース、発行物監査はPhase 2検証済みである。速度切替直後の音飛びは既知制約として許容し、Phase 2の阻害事項に含めない。4K WMVは性能保証外、HEVC・VFR・VP9は保証外のベストエフォートとする方針も確定済みである。
