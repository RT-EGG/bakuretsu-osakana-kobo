# v1.1.0 GitHub更新基盤 設計記録

更新日: 2026-08-24
状態: 実装中

## 1. 対象

`docs/specifications/specs.md` 15.3の`NEXT-UPD-001`～`NEXT-UPD-008`を対象とする。最初の縦スライスで、版比較、GitHub Release応答と対象assetの検証、24時間制御、最後の自動確認試行の保存、起動完了後の自動確認、手動確認メニュー、利用者向け結果表示を実装した。ダウンロード、別プロセスヘルパーによる置換と復旧は後続スライスとする。

## 2. Release確認

- 固定URL `https://api.github.com/repos/RT-EGG/bakuretsu-osakana-kobo/releases/latest`を認証なしで参照する。
- `Accept: application/vnd.github+json`、`User-Agent`、`X-GitHub-Api-Version: 2026-03-10`を明示する。
- GitHub側のlatest判定に加え、`draft=false`および`prerelease=false`を再検証する。
- 応答は1 MiBまでとし、JSON、必須フィールド、HTTPSの`github.com` URLを検証する。
- `BakuretsuOsakanaKobo-win-x64.zip`が1件だけあり、`uploaded`、sizeが正、digestが`sha256:`に続く64桁の16進数であることを必須とする。
- 403・429はAPI制限、その他のHTTP・通信失敗は利用不可、不正応答は別状態とし、どの場合も現行版を変更しない。

## 3. 版比較と間隔

- 外部パッケージを追加せず、SemVer 2.0.0の3要素、prerelease順序、build metadata無視を小さな純粋ロジックとして実装する。Release tagの先頭`v`だけはAPI境界で取り除く。
- 最後の自動確認試行は`settings.json`の省略可能UTC値とし、旧文書は未実行扱いにする。
- 前回試行から24時間以上で自動確認を許可する。システム時計が前回値より過去へ戻った場合は、無期限に抑止しないよう再確認を許可する。

## 4. ダウンロード準備

- 対象URLは固定リポジトリの`github.com/RT-EGG/bakuretsu-osakana-kobo/releases/download/`配下、asset名は`BakuretsuOsakanaKobo-win-x64.zip`へ固定する。
- ZIPは512 MiB、展開後合計は1 GiB、`release-manifest.json`は1 MiB、ファイルは10,000件を上限とする。取得前にZIP分、検証後に展開分の空き容量を確認する。
- sizeとGitHub SHA-256をストリーミング照合してからZIPを開く。各エントリもmanifest記載sizeを上限に読み、パス、size、SHA-256、ファイル集合を完全一致させる。
- 絶対・親参照・重複・リンク・Windows予約名・`data`配下を拒否し、framework-dependent `win-x64`、非single-file、非validation-only、製品EXEを必須とする。
- 一意な専用ディレクトリだけを所有し、通信・検証・容量・保存失敗と取消時は同ディレクトリを除去する。検証成功時だけ後続ヘルパーへ渡せるZIPとmanifestファイル一覧を返す。

## 5. ファイル置換トランザクション

- 更新ヘルパーから再利用するコードは`BakuretsuOsakanaKobo.Update`へ分離し、実行中本体やWPF・LibVLC・NAudioへ依存させない。
- 現行manifest所有ファイルと`release-manifest.json`をすべて専用バックアップへコピーし、flush後に元ファイルとのsize・SHA-256を再照合するまで対象ディレクトリを変更しない。
- 新版manifest所有ファイルだけを対象ディレクトリと同じ場所の一意一時ファイルへ耐久コピーし、同一ディレクトリ内のmoveで置換する。旧版だけが所有するファイルはバックアップ後に削除する。
- `data`、manifest外の未知ファイル、危険・重複パス、reparse point、重複・既存バックアップ領域を拒否または保全する。
- 変更開始前の取消は対象を不変に保つ。変更開始後の例外では、新版所有ファイルを除去してバックアップ全件を復元し、復元失敗を個別に返す。変更開始後は利用者取消を受け付けず、成功またはロールバックまで完走する。

## 6. 後続実装

1. [実装済み] アプリ版をAssembly情報から取得し、初回起動要求の処理完了後に非ブロッキング自動確認を開始する。手動確認はヘルプメニューから実行する。
2. [実装・実WPF検証済み] 自動確認は非モーダル通知、手動確認は版と最大600文字の概要を表示し、利用者が同意したときだけGitHub Releaseページを開く。
3. [実装・公開実ZIP検証済み] size上限、空き容量、digest、ZIP構造、manifestを検証するダウンロード準備を追加する。
4. [トランザクション核実装済み・次作業] 本体終了待ち、更新要求・結果契約、ZIP再検証と展開、トランザクション呼出し、再起動を行う専用ヘルパーホストを追加する。
