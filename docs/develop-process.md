# 基本的な開発の進め方

開発は大きく4段階に分ける。

## Phase1. 要求仕様の掘り下げ、整理

"docs\specifications\requirements_v.1.0.md" を確認し、要求を理解する。矛盾がある場合、開発者とすり合わせを行う。

決定した仕様について、 "docs\specifications\specs.md" に決定仕様のファイルを作成する。

また、機能の実装状況を管理するためのチェックリストを、 "docs\specifications\todo.md" に作成する。

## Phase2. 開発スタックの決定

使用する言語、ライブラリを決定する。

決定後、言語やライブラリの特性に応じた、コードレビュースキルを作成する。

## Phase3. UIの決定

"docs\specifications\specs.md" に従い、UI作成と開発者によるレビューを繰り返す。

この時、実際の機能を作り込む必要はない。なんらかの動作を含めたレビューが必要になる場合でも、裏側はモックアップで作成し、仮の表示を行えばよい。

言語やライブラリの問題でUIを実現できない場合、必要であればPhase2に戻ることも可能とする。

## Phase4. 動作の作り込み

"docs\specifications\specs.md"、"docs\specifications\todo.md" に従い、動作を実装する。
一度に大きな変更を入れず、適度な粒度でユニットテストやコミットを行う。

# ドキュメンティング

セッションの切り替えや、AIモデルの変更にも柔軟に対応できるよう、ドキュメンティングを行う。

# コードレビュー

コミットを行う前に、自己レビューを行う。
適宜、開発者へ確認した方がいいことがあれば、確認を行う。
