# 単一起動・ポータブルJSONスパイク

検証日: 2026-08-03  
対象: `P2-REM-05`、`SPIKE-005`、`SPIKE-007`  
結論: 合格

## 1. 検証構成

`.NET 10` / WPFだけを使う専用スパイクを
`spikes/SingleInstanceDataSpike`に作成した。外部パッケージは追加していない。

- `Local\\` Named Mutexで同じWindowsセッション内の一次プロセスを決定
- `PipeOptions.CurrentUserOnly`のNamed Pipeで二次起動から一次起動へ要求を転送
- 長さプレフィックス付きUTF-8 JSONとACKで、空白や日本語を含むパスを保持
- WPF Dispatcher上で最小化解除、表示、`Activate`、前面化を実行
- 実行ファイル相当ディレクトリ直下の`data`へバージョン付きJSONを保存
- 同じディレクトリの一時ファイルを`Flush(true)`後、`File.Replace`または`File.Move`
- 壊れたJSONを`.corrupt-<timestamp>`へ退避し、既定値で継続
- IO・アクセス拒否を保存失敗として返し、既存データを維持

## 2. 単一起動・IPC結果

`scripts/test-phase2-single-instance.ps1`の最終実行は全項目に合格した。

- 一次起動は1プロセスだけ残存
- 引数0個は既存ウィンドウのアクティベーションとして処理
- 引数1個は日本語・空白を含む絶対パスを文字単位で同一に転送・表示
- 引数2個は既存の表示パスを変更せず無視
- 3つの二次プロセスはACK受信後に終了コード0で終了
- 自動実行でも前面ウィンドウを観測

実画面試験では、別ウィンドウを前面にした状態から二次起動し、既存の検証ウィンドウが
前面へ戻ることと、`日本語 空白 動画.mp4`が表示されることを開発者が確認した。

`GetForegroundWindow`はテストランナー自身がフォーカスを取り返すと偽陰性になり得る。
したがって自動ゲートはIPC受理とアクティベーション処理までを判定し、OS上の最終的な
前面表示は手動ゲートを正とする。観測値は診断ログへ残す。

最終自動レポート:
`.tmp/single-instance-data/run-20260803104625746/report.json`

## 3. ポータブルJSON結果

日本語・空白を含む配置パスで次を全件確認した。

- 初回保存と読込
- 不完全な別一時ファイルがあっても既存JSONを維持
- 既存JSONの原子的置換
- 壊れたJSONの退避と既定値への復旧
- 読み取り専用ファイルへの保存失敗を報告し、既存値を維持
- 保存先が常に`<実行ファイル相当ディレクトリ>\\data`
- ストアが作った一時ファイルを残さない

最終自動レポート:
`.tmp/single-instance-data/data-report-final.json`

## 4. 採用判断と残存事項

Named Mutex + current-user-only Named Pipe、および同一ディレクトリ一時ファイルを用いた
JSON置換方式を製品実装へ採用できる。書込不可時は利用者へ警告し、メモリ上の状態で再生を
継続する。破損退避ファイルの整理UIや診断ログの具体的な見せ方はPhase 4で実装する。
