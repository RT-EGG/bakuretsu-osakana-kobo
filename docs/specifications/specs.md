## 1. 文書の読み方

この文書は初回リリースの動作仕様を定義する。要求書から直接確定できる内容には要求IDを付与し、実装と受け入れ確認の基準にする。

- `確定`: 要求書に明記されており、解釈に重要な分岐がない。
- `要確認`: 要求を実装可能な仕様にするため、開発者の判断が必要。
- `Phase 2検証`: 期待する結果は定義できるが、技術方式または保証範囲の検証が必要。
- `Phase 3決定`: UIレビューを通じて寸法、見た目、細かな操作感を決める。

Phase 1の要確認事項と補足提案はすべて開発者レビュー済みである。`Phase 2検証` と `Phase 3決定` は、それぞれのフェーズで具体化し、本書へ結果を追記する。

## 2. 対象範囲

### 2.1 初回リリース候補

`Q-001` では、動画再生と基本コントロールを先に提供し、その他の機能を段階的に追加する方針を決定した。

最初のリリースには次を含める。

- Windows 11向けのメインウィンドウ
- 「ファイル」メニューの「開く」からmp4/wmvを選択
- 選択した動画の自動再生
- 再生・一時停止
- 現在位置の表示と操作ができるシークバー
- `hh:mm:ss / hh:mm:ss`形式の現在位置・全体時間表示
- 上記を配布物として起動し、エラー時にアプリが異常終了しないための最小限の基盤

音量・ミュート、再生速度、フルスクリーン、サムネイル、ショートカット、ドラッグ&ドロップ、起動引数・関連付け、動画プロファイル、プレイリスト、最近開いたファイル、複数のメイン再生ウィンドウ、キーバインド編集、Windows 11以外のOSの正式サポートは、最初のリリース後の追加対象とする。

### 5.3 音量とミュート

| ID | 状態 | 仕様・受け入れ条件 |
| --- | --- | --- |
| VOL-001 | 確定 | マウスで操作可能な音量インジケーターを提供する。 |
| VOL-002 | 確定 | 音量範囲は0～500%、100%を動画本来の最大音量とする。 |
| VOL-003 | Phase 2検証 | 100%を超える値はソフトウェアで増幅し、リミッター等でピークを抑制する。元音源や出力環境によって、歪みなく体感音量が5倍になることまでは保証しない。具体方式と品質はPhase 2で検証する。 |
| VOL-004 | Phase 3確定 | 動画再生領域上のマウスホイールで音量を変更する。1ノッチあたり5%増減し、0～500%の範囲を越えない。2026-08-08開発者承認。 |
| VOL-005 | 確定 | ミュートとミュート解除を切り替えられる。 |
| VOL-006 | 確定 | 音量またはミュート状態の最後の変更から3秒後に、動画プロファイルへ自動保存し、動画切替前と正常終了時にも保存する。次回は動画ごとに保存した音量とミュート状態を復元する。2026-08-11開発者承認。 |
| VOL-007 | Phase 4改訂 | 0～500%音量とミュートはアプリ内PCM処理を正とし、WASAPI出力開始時に製品のアプリ別音量セッションを100%・非ミュートへ同期する。Windowsの既定出力選択とエンドポイント全体の音量・ミュートは変更しない。アプリ別セッションに残った状態によって画面の非ミュート表示と実出力が食い違わないこと。2026-08-15候補レビュー指摘により追加。 |

### 5.4 再生速度

| ID | 状態 | 仕様・受け入れ条件 |
| --- | --- | --- |
| SPEED-001 | 確定 | 0.25、0.5、1.0、1.5、2.0倍速を選択できる。 |
| SPEED-002 | 確定 | 動画を開いたときの既定速度は1.0倍とする。 |
| SPEED-003 | 確定 | 動画再生領域の右クリックメニューから速度を切り替えられる。 |
| SPEED-004 | 確定 | 動画再生領域を左ボタンで400ms以上押し続けると、一時的に2.0倍速で再生する。ボタン解放またはウィンドウのフォーカス喪失時に、長押し前の速度へ戻す。 |
| SPEED-005 | 確定 | 発動前にドラッグ判定距離を移動した場合は長押しを発動しない。発動後のマウス移動では解除しない。 |
| SPEED-006 | 確定 | 長押し時間は既定400msの設定値として一元管理し、Phase 3で調整可能にする。設定値を変更する利用者向けUIは初回リリースで必須としない。 |

再生速度は最初のリリース後の低優先度機能として扱う。LibVLCの速度切替直後には短い音飛びが
発生し得ることを既知制約として許容し、シームレスな音声切替は受け入れ条件に含めない。
各速度での継続再生中に、目立つ音切れ、不自然なピッチ変化、A/Vずれがないことを確認対象とする。

## 6. キーボードショートカット

`Alt+Enter`とフルスクリーン中の`Esc`は入力フォーカスにかかわらず扱う。その他の再生ショートカットは、ボタン、スライダー、コンボボックス、メニューなどの入力要素にフォーカスがある時は扱わず、各要素の標準キー操作を優先する。2026-08-08にPhase 3で開発者承認。

| ID | 状態 | キー | 動作 |
| --- | --- | --- | --- |
| KEY-001 | 確定 | Space | 再生と一時停止を切り替える。 |
| KEY-002 | 確定 | ← | 現在位置から5秒戻る。5秒未満の場合は00:00:00へ移動し、先頭より前には移動しない。 |
| KEY-003 | 確定 | → | 現在位置から5秒進む。残り時間が5秒未満の場合は末尾へ移動し、それより後には移動しない。 |
| KEY-004 | 確定 | ↑ | 定義済み速度の一段上へ変更する。2.0倍時は変更せず、2.0倍を維持する。 |
| KEY-005 | 確定 | ↓ | 定義済み速度の一段下へ変更する。0.25倍時は変更せず、0.25倍を維持する。 |
| KEY-006 | 確定 | Alt+Enter | フルスクリーンを切り替える。 |
| KEY-007 | 確定 | 内部設定 | 割り当てはコード上で一元管理し、将来の編集機能を妨げない。初回リリースでは利用者向け編集UIを提供しない。 |

| LIST-026 | 確定 | ループの既定値はOFFとする。ON/OFF状態は設定として保存し、次回起動時に復元する。 |
| LIST-027 | 確定 | ループONでも再生可能な項目が1件もない場合は停止し、一度だけ案内を表示する。 |

## 10. エラー処理とデータ保全

| ID | 状態 | 仕様・受け入れ条件 |
| --- | --- | --- |
| ERR-001 | 確定 | 別動画の再生開始前に読み込み失敗を判別できた場合、現在の動画があればその動画と再生位置を維持する。現在の動画がない場合は未選択状態へ戻る。プレイリスト連続再生中は詳細をログへ記録し、次の再生可能項目へ進む。再生開始後に途中破損が判明した場合は元動画へ戻さず、再生中エラーとして案内・記録する。 |
| ERR-002 | 確定 | 設定、プロファイル、プレイリストの一部が不正でも、アプリ全体を起動不能にしない。問題のあるデータについて警告とログを残し、安全な既定値または空データで起動を継続する。 |
| ERR-003 | 確定 | 永続データを更新するとき、途中終了で既存データ全体を破損させにくい方式を採用する。一時ファイルへ完全に書き込んでから置き換える方式など、具体方式はPhase 2で決める。 |
| ERR-004 | 確定 | 画面には利用者が次に取れる行動が分かる簡潔なメッセージを表示し、例外情報、内部エラー、対象パスなどの診断用詳細はログへ記録する。長い技術情報やスタックトレースを画面へ直接表示しない。 |

## 12. 主要状態

実装とUIレビューでは、少なくとも次の状態を区別する。

1. 動画未選択
2. 読み込み中
3. 再生中
4. 一時停止中
5. シーク中
6. 一時的な2.0倍速再生中
7. 読み込みエラー
8. フルスクリーン
9. プレイリスト連続再生中

状態間の詳細な遷移と表示は、未決事項の解消後、Phase 3のUI仕様で確定する。
