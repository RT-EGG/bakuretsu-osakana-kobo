# WPF UI・ウィンドウ技術スパイク

実施日: 2026-08-03  
対象: `P2-REM-04`  
構成: .NET 10 / WPF / 外部パッケージなし

## 目的

画面デザインを確定する前に、WPFで次の技術要件を実現できるか確認する。

- 再生バックエンドをUIから分離し、実動画なしのモックへ差し替える。
- プレイリスト等を別のネイティブウィンドウとして表示する。
- シークバー上にホバーポップアップを表示する。
- 現在のディスプレイでフルスクリーンへ入り、元の状態へ戻す。
- 複数ディスプレイ間の移動、DPI変更、フォーカス、前面化を処理する。

## 実装

`spikes/WpfWindowingSpike`へ専用スパイクを追加した。動画ライブラリには依存せず、
`IPlaybackBackend`へ`MockPlaybackBackend`を注入して、再生、一時停止、シーク、時刻更新を模擬する。

UIには次を実装した。

- 独立したHWNDを持ち、メイン画面をownerとするプレイリストウィンドウ
- WPF `Popup`によるモックサムネイルと時刻
- ボタン、右クリックメニュー、動画領域のダブルクリック、`Alt+Enter`によるフルスクリーン切替
- `Esc`によるフルスクリーン解除
- フルスクリーン中のコントロール表示と、2秒後の自動非表示
- Win32モニター列挙、ウィンドウ矩形・DPI・foreground取得、別画面への移動

自動検証モードは実ウィンドウを表示し、各状態を操作した後にJSONレポートを出力する。

## DPI修正と再検証

開発者確認により、実際のWindows設定は1画面が100%、2画面が150%だった。初回レポートで
すべて96 DPIとなった原因は環境ではなく、スパイクがPer-Monitor DPI awarenessを明示していなかった
ことにある。`app.manifest`へ`PerMonitorV2, PerMonitor`を追加して再検証した。

- Primaryは96 DPI、2台のSecondaryは144 DPIを取得した。
- 100%画面の1000×650物理pxから、150%画面の1500×975物理pxへ再スケーリングした。
- 3画面すべてで対象画面内への移動とforeground維持に合格した。
- フルスクリーンは現在画面を維持し、元の位置・サイズへ復帰した。

## 実画面確認と製品実装へ送る事項

開発者が100% / 150%画面で実画面を確認し、別ウィンドウ、フルスクリーン、DPI切替、主要配置に
問題がないと判断した。シークPopupの初期`MousePoint`配置では追従不良と画面原点への移動があり、
シークバー基準の`Relative`配置、左右端クランプ、カーソルより上への配置へ修正した。修正版は
左右追従、原点への飛び、左右端の表示について「完璧に近い」と開発者確認された。

サムネイルとシークバーの上下間隔、およびPopup上をマウスが通過しても閉じない処理は、
技術スタックの阻害事項ではない。Phase 3で配置を調整し、Phase 4の製品実装でPopupを
マウス入力対象外にする方式を確認する。以上により`P2-REM-04`を完了とする。
