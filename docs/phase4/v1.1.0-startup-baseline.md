# v1.1.0 起動区間ベースライン

測定日: 2026-08-29

対象: `NEXT-START-001`

生データ: `docs/phase4/results/v1.1.0-startup-baseline.json`

## 1. 測定方法

- framework-dependent `win-x64`の製品発行物を一意な一時ディレクトリへ生成し、条件ごとに別プロセスで5回起動した。
- `BOK_STARTUP_TRACE_PATH`が指定された測定時だけ、製品`App.OnStartup`が単調増加時計で区間を記録する。通常起動では計測器を生成しない。
- 操作可能点は、`ContentRendered`、Dispatcher `ApplicationIdle`、初回起動要求完了、非ブロッキング自動更新確認の開始がすべて完了した時点とした。
- `first-empty`は各回で`data`を削除する。`existing-empty`は4つの有効なschema 1文書を空データで用意する。`existing-file-muted`は同じ4文書と100%ミュートの動画プロファイルを用意し、5秒H.264/AAC MP4を起動引数で渡す。
- 各プロセス終了後は1秒待つ。ファイル引数条件は計測後に2秒安定待ちしてから通常終了する。OSファイルキャッシュは消去しないため、ハードウェアの完全コールドブートではなく、別プロセス・新規発行先によるコールド相当測定である。

反復時の操作可能中央値は1,101.70～1,191.34 msで、既存の1,500 ms基準内だった。最大の中央値寄与は`Show`呼出し376.85 ms、Window生成279.90 ms、LibVLC初期化181.55 ms、Show返却から`ContentRendered`まで100.03 ms、設定初期化37.61 msである。

一方、新しい発行先の最初の1プロセスはLibVLC初期化だけで11,780.21 ms、操作可能まで13,280.22 msを要した。別の新規発行先による追加測定でもLibVLC初期化11,325.95 ms、操作可能12,772.58 msとなり、最初のネイティブ資産ロードに結びつく再現性のある主要因と判断する。同じ発行物の2回目以降はLibVLC初期化172～185 ms程度へ戻った。

## 3. 判断と次の作業

- `NEXT-START-001`の目的である区間別測定、空起動とファイル引数起動の分離、主要因特定は完了した。
- `ThumbnailGenerationService`自身の構築は中央値0.5 ms未満であり、現状の主要因ではない。ただし内部LibVLC初期化を将来遅延する場合は、主再生バックエンドと同じライフサイクル境界で扱う。
- `Show`より前に主再生用LibVLCを必ず生成する現在の順序は、新規発行物の最初の空起動を約12秒ブロックする。`NEXT-START-002`では空の操作可能シェルを先に表示し、主再生・サムネイル初期化を必要時または表示後へ移す案を第一候補とする。
- 4つの永続Repositoryは合計でも反復中央値約66 msだが、ファイル引数処理の順序と設定警告を維持できる範囲で遅延または安全な並列化を検討する。
- 計測レポート直後にファイル起動プロセスを閉じる人工的な条件では、通常終了が15秒および30秒を超える事象を各1回観測した。計測後に2秒待つ最終15回では全件正常終了した。初期化・映像出力が進行中の終了取消と破棄は`NEXT-START-002`の回帰確認へ含める。
- 改善後の数値目標は、遅延初期化後の再測定結果を提示して開発者レビューで確定する。現時点では既存1,500 ms基準を変更しない。
